On web, use rollback journal/FULL and single ownership instead of assuming native WAL behavior. Actual browser support must be tested before claiming durable writes.

Expo documents its current [web SQLite support as alpha](https://docs.expo.dev/versions/latest/sdk/sqlite/). The initial Vite SPA therefore has its own qualified browser executor; selecting Expo for native distribution does not force its web database binding into this stage. Read SDK-version-pinned docs when the native project exists. Code migration shares the schema/logic; actual parent data moves only through the required explicit protected backup/restore flow, not through installing Expo. SPA/native format interoperability is qualified with shared fixtures.

## State and migration boundaries

Pure shared TypeScript owns graph execution, corrections/review queues, canonical ink/history, progress/results and source provenance. The coordinator is the sole command authority. SQLite is durable truth. React Query exposes cached committed read models and command mutations; transient view state uses React state. Pointer samples never enter Query cache. Source-derived labels and highlighted app-origin copy apply to shadcn and native controls equally.

After a successful transaction, publish/invalidate only affected queries. Local-store reads run independently of network availability; package downloads use network-aware execution. Instructional mutations use no automatic replay: explicit Retry reuses command IDs, revisions and hashes. Reset/delete cancels outstanding work, removes owner-scoped cached projections, and rejects late generation results. Reopening the app reconstructs from SQLite, not from a persisted query cache. Native query managers integrate AppState/connectivity without resetting the teaching engine.

SPA stage completes all application functionality and shared contract fixtures first. After all 45 tasks and the full profiles/progress/Undo/offline/backup/recovery gate passes, add Expo Router/screens and replace browser-only adapters incrementally: native DB, files, lifecycle, gestures and ink renderer. Reuse the shared engine, schema/queries/migrations, source-aware projection data, tokens and acceptance fixtures. shadcn screen implementations remain web-specific; do not promise a UI conversion or use a permanent WebView to bypass native writing requirements. Physical-device gates remain required before release.

## Backup and profile technology contract

Profile commands use stable IDs, generations, expected revisions and durable receipts. Confirming an avatar changes only the selected profile preference; cancel does not write. Unknown/missing bundled animal keys use a non-mutating display fallback. Display names are optional and never ownership keys.

The portable backup format includes consistent profile/run/Undo/credit/ink/history/preferences snapshots and exact pinned runtime packages. Select a reviewed authenticated-encryption primitive, passphrase KDF and bounded versioned container before implementation. Pin actual crypto/KDF libraries and parameters against qualified browser/native vectors; no unimplemented or unauthenticated homegrown cipher is accepted. Export uses fresh entropy and never logs keys/passphrases. Restore validates integrity, schema, ownership, size and codec compatibility before atomically creating new IDs with parent preview/rename. Existing profiles never merge or overwrite. Native file/share and crypto adapters must interoperate with SPA fixtures. Raw scans/development artifacts remain excluded; only publication-approved runtime content is distributable.

Qualification covers wrong passphrases, tamper/truncation, unsupported versions, resource limits, cancellation, interrupted export/import, duplicate names, unknown avatar IDs and offline restored correction/writing/Undo. Backup protection does not provide account recovery or automatic cloud synchronization.

## Formatting and commit gate

The root package is tooling-only today. `npm run format` formats all supported authored files, and `npm run format:check` verifies them. Binary assets, dependencies and generated build output are excluded; Prettier skips unsupported formats. Preserve source/transcription wording when formatting Markdown/JSON. No ESLint configuration/dependency or custom Prettier options/plugins may be introduced by SPA/Expo scaffolding.

Husky runs lint-staged to format staged files, then the whole-project formatting check. Git is initialized and the hook is enabled. Run `npm run prepare` after cloning/installing to activate the hook in that checkout. Typecheck/tests will be added to the gate when real scripts exist; no placeholder passing scripts are created. CI must run the formatting check independently. The formatter enforces default style; domain/type tests enforce behavior.

## Signed bytes and artifacts

`ManifestBody` contains course/release/schema/capability metadata, cumulative ordered lesson IDs, a curriculum entry with path/SHA-256/length/media type, every runtime asset entry, source-review manifest hash, and reviewed compatibility/progress mappings. `packageHash = SHA256(UTF8(JCS(ManifestBody)))`. Source-review data includes its hash in this body, not private workstation paths.

The unsigned envelope is `{formatVersion: 1, body: ManifestBody, packageHash, signingKeyId}`. The Ed25519 signature covers **exactly** `UTF8(JCS(unsignedEnvelope))`; the transmitted envelope adds `signature` as base64url without padding. Verify canonical transmitted UTF-8 bytes by round-trip byte equality, validate the schema, recompute body hash, verify signature with the trusted key, then verify curriculum/assets against body hashes. This rejects duplicate JSON keys/noncanonical encodings before using the package. Hashes do not include their own field or signature. Trust-key additions/revocations require a trusted application/trust-bundle release; downloaded content cannot replace its own verifier keys.

Every release retains immutable application artifacts, content files/manifests, checksums/signatures, source-review report, exact lockfiles/toolchains, dependency notices, schema/codec decoders, migration fixtures, and test reports. Keep each published release and its recovery artifacts while any installed state can require it; do not expire pinned-package compatibility on a rolling “last two versions” rule. Distribution-host retention and any later end-of-support policy need an explicit reviewed migration/recovery plan.

On each selected dependency upgrade: review upstream changes/security advisories and license notices, regenerate reproducible content, run decoder/signature golden vectors, run the relevant graph/storage/ink/lifecycle fixtures, and record the release's supported matrix. Native SDK upgrades include physical-device checks. Installed formatting-tool versions are recorded above and in the root lockfile. Application dependencies remain selected designs until their projects/manifests are created and verified.
