# Architecture review acceptance matrix

**Revised:** October 16, 2026. Reconciled with the accepted interview decisions and ADRs. These cases define required implementation evidence for [the architecture](../../ARCHITECTURE.md). **Execution status: not run.** This repository contains source/design documents, not the application, real storage adapters, or device test harnesses. Documentation consistency checks do not establish runtime correctness.

Use stable fixture IDs and exact package hashes. Tests observe teaching position, visible saved ink, durable results, and permitted actions. They must exercise real storage transactions and process/adapter restart where specified. Mocks alone do not satisfy storage/publication cases. Every recovery/error/control label passes the source-aware renderer with app-origin highlighting.

## SPA-first / Expo migration acceptance

Build all SPA functionality and shared TypeScript contracts first. After the entire SPA functional gate below passes, run identical graph/result/ink/storage fixture data against the SPA worker and Expo executors. Verify identical outcomes, correction/review routes, SQL constraints, canonical BLOB geometry and old-state migrations; adapt screen/input behavior with native device checks rather than promising DOM component reuse. Enforce the import boundary between shared domain code and browser/Expo/React Query modules.

The full-functional-SPA handoff is a hard dependency of native adaptation. Verify every source step/item/correction/review route in all 45 tasks, all six real writing tasks, parent preparation, profile/animal onboarding, map/override/replay, Back/Undo, saved editable ink, offline cold launch and package updates, protected complete backup/restore-as-new, and fault recovery together. Run real OPFS restart/transaction tests and browser UI coverage, source/glyph review, stable-anchor/provenance/accessibility/window checks and import-boundary enforcement. Partial samples, mock stores, a green build or a documentation check do not satisfy this gate. Native polish and physical ink latency are separately required on both tablet platforms; no educational-efficacy study gate applies.

First public release requires a qualified iPad candidate and Android tablet candidate with exact device/OS/toolchain/driver support matrices, signed build provenance and physical ≤50 ms p95 input-to-visible-ink evidence during 30 seconds of continuous drawing with saves. Retain clock limits/methodology. Require source/runtime asset/backup redistribution approvals, child-directed declarations, provisioning and explicit submission/release authorization. Missing external inputs remain blockers, not completed acceptance. Phones and permanent public web service are outside the launch promise.

React Query integration tests must cover local reads without connectivity, committed-only teaching projection, no optimistic completion, explicit same-ID Retry, and late cached read/mutation responses after profile reset. A refetch or focus/network event cannot restart a task run or advance a lesson. Validate native AppState/connectivity bindings separately from browser window events. Unavailable browser durable storage must stop normal teaching with a recoverable state, not switch silently to memory.

The development gate checks default Prettier formatting for every supported authored file and forbids ESLint configuration/dependencies introduced by scaffolding. Test the real pre-commit hook with staged unformatted files in an isolated Git fixture. Application typechecks and behavioral tests join the gate when their actual scripts exist; do not create placeholder passing tests. Formatting/hook evidence is distinct from the unexecuted application acceptance cases above.
