# SQLite browser compatibility

Issue #2 selects `@sqlite.org/sqlite-wasm` 3.53.4-build2, SQLite's official ES-module distribution, for one worker-owned `opfs-sahpool` connection. The wrapper has Apache-2.0 notices; SQLite core is public domain. Exact locked artifacts and bundled notices remain release inputs.

Inspection of this artifact found that `installOpfsSAHPoolVfs` calls `removeVfs` after initialization failure. That cleanup recursively deletes its managed directory. A failed open must preserve existing personal data, so the build applies one checked change to the initializer's failure path. It releases access handles and rethrows instead of deleting the pool. The failed worker is then terminated. Successful operation and the SQLite/WASM binary are unchanged.

The build transform checks the original artifact's SHA-256 and requires the cleanup occurrence exactly once. A dependency change fails the build until reviewed. No dependency installation is silently rewritten. Both Vite development and production worker builds must use this transform. The real-browser qualification must seed saved teaching, force initialization failure through an actual held OPFS file handle, release it, reopen and verify saved state and bytes. A string comparison alone does not establish preservation.

Upstream's [current persistence documentation](https://sqlite.org/wasm/doc/trunk/persistence.md#vfs-opfs-sahpool) describes a `preserveOnInitFailure` option added in SQLite 3.54. The pinned 3.53.4 artifact lacks that option. A future supported release can replace the local transform after the same restart/failure suite passes. The held-file fault test now passes in both Vite development and built production workers: all six seeded pool-file hashes remain identical after initialization failure, and reopening restores the child-response turn. Full browser-process restart, competing-tab ownership and lost-COMMIT-reply recovery pass too. Qualification currently covers headless Chromium 156 on the development host; it does not establish supported tablet hardware, Safari, native SQLite or the complete application matrix. See [the evidence record](../evidence/issue-02.md).
